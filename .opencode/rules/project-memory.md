# Память проекта — NetworkScaleLabel

Сюда записываем принятые решения и поправки, чтобы не переоткрывать их заново.

---

## 1. Расположение проекта — ASCII-путь (обязательно)

**Путь:** `D:\AIHub\ProjectsAI\NetworkScaleLabel`

Репозиторий **перенесён** из `D:\AIHub\ProjectsAI\СетевыеВесыАндроид\NetworkScaleLabel`.

**Причина:** кириллица в пути ломает сборку на Windows.
- `assembleDebug` падал с `non-ASCII characters ... will most likely cause the build to fail`.
- Заглушка `android.overridePathCheck=true` **не лечит**, а только глушит предупреждение.
- После заглушки APK собирался, но **unit-тесты падали**: `ClassNotFoundException` на
  скомпилированные классы тестов (классы на месте, раннер их не видит — классика сломанного
  classloader из-за не-ASCII в URL classpath).

**Решение:** держать репо только в ASCII-пути. Заглушку **не возвращать**.
Каталог `D:\AIHub\ProjectsAI\СетевыеВесыАндроид` оставлен как «домашний»: драйверы Штрих,
собранные APK, логи.

## 2. Весы и сеть (факты с железа)

- **Весы:** ШТРИХ-ПРИНТ 15-2.5, протокол **UDP**, порт **1111**, пароль **0030**.
- **Текущий IP весов:** `192.168.0.52` (сменён с `192.168.140.89`).
- **Телефон:** `192.168.0.148/24` (Wi-Fi `MSSO-IT-5GHz`), он же `10.164.133.35/24` по USB (rndis0).

**Важный вывод про «connect: -1» (не закрыт до конца):**
Раньше весы были в `192.168.140.x` — **чужая подсеть** для телефона. Замеры дали:

| Тест | чужая подсеть | своя подсеть (0.52) |
|---|---|---|
| ping из shell-UID | работает | работает |
| ping из **UID приложения** | **100% потерь** | работает |
| UDP `02 01 11` из **UID приложения** | **0 байт** | **76 байт** ответа |

То есть трафик в чужую подсеть под UID приложения не проходил, при этом shell-UID работал.
Роутер при этом слал `ICMP Redirect` с перевёрнутым адресом `89.140.168.192`.
**Перенос весов в свою подсеть (`192.168.0.52`) проблему снял.**

Точная строка `connect: -1` **не найдена** ни в исходниках, ни в dex — собирается в рантайме.
Похоже на `message` от `DatagramSocket.connect()`. **Вывод не доказан** — при повторении
ошибки смотреть настоящий стектрейс, см. п.3.

## 3. Логирования в приложении НЕТ (надо добавить)

Во всём `app/src/main` нет ни `Log.`, ни `Timber`, ни `println`. Это **противоречит `AGENTS.md`**
(«`try/catch` без логирования и обработки — запрещено») и мешает отлаживать: реальной причины
ошибок не видно.

**Правило на будущее:** каждый `catch` — с логированием класса, `message` и стектрейса.
При любой непонятной ошибке **первым делом** смотреть `logcat`, а не гадать.

## 4. Рабочий цикл сборки (проверено)

```bash
./gradlew assembleDebug     # сборка APK
./gradlew test              # unit-тесты (47 шт., debug + release = 94 прогона)
```

- **JDK:** `C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot` (переменная `JAVA_HOME`)
- **Android SDK:** `D:\Android\AndroidSDK` (прописано в `local.properties`)
- **Установка на телефон:** `adb` = `D:\Android\AndroidSDK\platform-tools\adb.exe`
- Инкрементальная пересборка ~**9–16 с**.
- APK выкладывается в `D:\AIHub\ProjectsAI\СетевыеВесыАндроид\` — **ставить пользователю вручную**.

**⚠ Подпись:** локальная debug-подпись **не совпадает** с той, что была у старого APK.
При обновлении `adb install -r` даёт `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — старое приложение
нужно **удалять**. Пользователь предпочитает ставить APK сам.
